# Dev.19 critique repairs — PRE-ALPHA release

The courier's newest enemy is two departments stamping the same form at once. This candidate repairs restore ownership and scheduler progress. The separately authorized dev.19 publication binds these tested server bytes to the matching release assets; older releases stay immutable.

## Changed boundaries

- Restore intent belongs to its initializer. Marker writers use one stable sibling lock file and atomic replacement; an older completion cannot clear a newer pending epoch. The marker schema stays `correspondence.restore.v1`. PostgreSQL and filesystem updates are not one atomic transaction: an interrupted or inconsistent transition stays quarantined rather than guessing which init won.
- A cooling-down recipient no longer blocks every other offscreen correspondent. Case variants in relationship names resolve to one canonical contact key, using the lowest valid affinity when values conflict. Prompt construction is validated before an initiation claim.
- Failed source construction is deferred for reconsideration instead of pinning the oldest candidate window. Fresh and due deferred sources each have reserved bounded scan capacity. The NPC map is fetched once per autonomy attempt. Deferral does not consume a model call or authorize delivery; every reconsideration repeats source, identity, restore and eligibility checks.
- Production initialization failures are bounded within the request. Dedicated connections must be idle at transaction boundaries, and reader paths cannot render notes or invoke writers. Shared-lock acquisition retains its pre-snapshot protection and restores the caller's session timeout. Optional consumer calls must return an idle connection; a leaked transaction cannot become somebody else's successful commit.
- Diagnostics retain `claim_changed` and `restore_unavailable` as specific reasons. A safe operator close records an anchored administrative decision, separately from physical delivery. It cannot resend, refund, assert failure or turn an unknown into a safe retry. Late genuine receipts and read-only reconciliation remain valid.
